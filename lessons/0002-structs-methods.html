Структуры, методы и указатель vs значение

Данные в Go живут в структурах, поведение — в методах. А главная развилка урока — указатель или значение. Это второй из трёх рефлексов курса: в Go значения копируются. Пропустишь эту идею — будешь ловить баги «поменял, а не поменялось».

Что ты сможешь после урока Объявить struct, создать его, повесить на него метод, и осознанно выбрать ресивер по значению или по указателю — понимая, кто получит копию, а кто оригинал.

💡 В тёмных блоках жми ▶ Запустить — Go выполнится в браузере. Код можно менять прямо в поле.

Быстрый повтор Урока 1 Помнишь zero value? У каждого типа есть значение по умолчанию, «undefined» в Go нет. Это правило сейчас пригодится: у новой структуры все поля сразу имеют zero value — без всякой инициализации.

1. Структура — форма данных

Структура объединяет именованные поля под одним типом. Это главный способ хранить данные в Go (аналог типа-объекта из TS, но это и тип, и сами данные сразу).

Если пришёл из TS В TS тип и объект — раздельно: interface User + литерал {...}. В Go type User struct{...} — это сразу и тип, и «класс данных». %+v в Printf печатает поля с именами — удобно для отладки.

2. Метод — поведение на структуре

Метод — это функция с ресивером: маленький аргумент в скобках перед именем. Он говорит, к какому типу привязан метод.

Ресивер = твой this В TS метод внутри класса, а this — неявный. В Go метод объявлен снаружи, а «this» назван явно: u в (u User). Заодно вспомни Урок 1: Greeting с большой буквы — значит публичный (виден из других пакетов).

3. Развилка урока: указатель vs значение 🔑

Ресивер бывает двух видов, и разница огромная:

  • (u User) — по значению: метод получает копию. Меняешь поля — меняется копия, оригинал цел.
  • (u *User) — по указателю: метод получает адрес оригинала. Меняешь поля — меняется оригинал.

Рефлекс #2 курса: значения копируются В TS объект — это ссылка: передал в функцию, поменял поле — поменялось везде. В Go структура копируется при передаче. Хочешь менять оригинал — бери ресивер *User. Забыл звёздочку — «поменял, а не поменялось». Это источник багов №1 у тех, кто пришёл из JS/TS.

Какой ресивер реально изменит поле оригинала?

Практическое правило (пока такое) Метод меняет структуру или структура «тяжёлая» → бери *T. Метод только читает и структура маленькая → можно T. Не мешай у одного типа: если хоть один метод на *T — делай все на *T. Это идиома, дальше объясню почему.

4. Конструктор + возврат ошибки

В Go нет слова new как в TS. Идиома — функция NewX, которая собирает структуру и (если может пойти не так) возвращает (*X, error). Вот и повтор рефлекса #1 из Урока 1 — ошибки как значения.

Зачем это на бэкенде Так выглядит половина твоего будущего сервиса: NewService(...), NewRepository(...) — конструктор проверяет зависимости и возвращает (*T, error). &User{} = «дай адрес», *u = «дай значение по адресу». Эти два значка (& и *) — весь базовый набор по указателям.
