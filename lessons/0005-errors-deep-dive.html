Ошибки — обёртывание, errors.Is/As, свои типы

Рефлекс #1 — «ошибки это значения» — ты уже знаешь с Урока 1. Но if err != nil — это только начало. На бэкенде нужно ещё: добавить контекст к ошибке, не потеряв исходную; отличить «не нашли» от «сломалось»; и прочитать детали из своей ошибки. Для этого — обёртывание, errors.Is, errors.As.

Что ты сможешь после урока Обернуть ошибку контекстом через %w, проверить конкретную ошибку в цепочке через errors.Is, и достать свой тип ошибки через errors.As, чтобы прочитать его поля.

💡 В тёмных блоках жми ▶ Запустить — Go выполнится в браузере. Код можно менять прямо в поле.

Быстрый повтор Уроков 1 и 4 Урок 1: ошибка — это просто значение, проверяем через if err != nil, без try/catch. Урок 4: error — тоже интерфейс, всего с одним методом Error() string. Сегодня своя структура-ошибка это использует напрямую.

1. Обёртывание: %w сохраняет исходную ошибку

fmt.Errorf("...: %w", err) добавляет контекст, но не «прячет» исходную ошибку — её можно достать позже через errors.Unwrap или найти через errors.Is/errors.As.

Если пришёл из TS Похоже на throw new Error("контекст", { cause: err }) (ES2022) — тоже сохраняет причину. Отличие: в Go есть более старый способ напечатать ошибку без связи — %v вместо %w. Текст будет тот же самый, но errors.Is/errors.As после %v уже не найдут исходную ошибку — связь потеряна.

Чем fmt.Errorf("...: %v", err) отличается от fmt.Errorf("...: %w", err)?

2. Sentinel-ошибка + errors.Is

Sentinel — это ошибка-константа уровня пакета (var ErrX = errors.New(...)), которую сравнивают не через ==, а через errors.Is — она умеет разворачивать цепочку обёрток.

Рефлекс #1, ещё один поворот == сравнивает ошибку буквально — а обёрнутая ошибка это уже другое значение (обёртка поверх). errors.Is разворачивает цепочку через Unwrap и ищет совпадение внутри. Поэтому для sentinel-ошибок в идиоматичном Go — всегда errors.Is, никогда ==.

err обёрнут через %w вокруг ErrNotFound. Как правильно проверить, что внутри именно она?

3. Свой тип ошибки + errors.As

error — это интерфейс с одним методом (Урок 4). Значит своя структура с методом Error() string тоже является ошибкой — и может нести дополнительные поля.

Is vs As — когда что errors.Is(err, ErrX) — «это конкретно та же ошибка (или обёртка над ней)?» — для sentinel-значений. errors.As(err, &target) — «есть ли в цепочке ошибка вот такого ТИПА, и если да — дай мне её, чтобы прочитать поля» — для своих структур-ошибок с данными внутри.

Зачем нужен errors.As, если уже есть errors.Is?
